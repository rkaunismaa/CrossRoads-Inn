# Grey-box Godot Prototype Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A playable grey-box week of Crossroads Inn in Godot. Its GDScript rules reproduce the Python simulation's ledgers exactly, and Bram speaks fixed lines chosen from a facts object.

**Architecture:**
- Python exports the tuned params (`game/data/params.json`) and dealt runs with expected ledgers (`game/tests/fixtures/*.json`).
- A GDScript port of the rules (`game/scripts/rules/`) is driven step by step through `DayRunner`. The UI and the parity test both use it.
- Bram (`game/scripts/bram/`) only reads a facts Dictionary and returns text.
- The counter-layout UI (`game/scenes/main.*`) only calls `DayRunner` and `Bram`.

**Tech Stack:**
- Godot 4.7.2 with typed GDScript.
- GUT 9.7.1, run headless via `tools/run-tests.sh` (extra args pass through, e.g. `-gtest=res://tests/unit/test_rules.gd`).
- Python 3.10 with pytest for the exporters.

**Spec:** `docs/superpowers/specs/2026-10-23-greybox-godot-design.md`

## Global Constraints

- Godot 4 syntax and typed GDScript only (`@onready`, `@export`, `signal.connect()`). Never use Godot 3 APIs.
- Rule scripts extend `RefCounted` (no nodes), live in `game/scripts/rules/`, and are testable headless. UI code holds no game rules.
- No balance numbers are hard-coded in GDScript. Every value comes from `res://data/params.json`, which `python3 -m inn_sim export` writes from `prototype/balance.ods`.
- Ledger strings are byte-identical to Python `inn_sim`'s:
  - `Day {d}: could not pay upkeep, run lost`
  - `Day {d}: {weather}, {n} travelers, coins {c} food {f} firewood {w}`
  - `Day {d} slot {s}: {kind_shown} -> {action}: {outcome}`
  - `Day {d} night: {notes}; now coins {c} food {f} firewood {w}`
  - `End: {c} coins vs debt {debt}: WIN|LOSS`
  - Outcome and night-note wording comes from `prototype/inn_sim/rules.py` (`serve`, `night`, `describe_news`).
- Rounding copies Python's round-half-to-even (`InnRules.py_round`) wherever the rules round.
- Bram reads only a facts Dictionary and never touches `InnState`. His facts never include `is_thief`, `noble_tier` or `goodwill`, and include the final event only once it has been announced in news or has happened.
- After each task, append a step to `docs/session-history.md` and commit. Messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **`params.json` is missing, or a key is missing**, for example after someone adds a param in Python and forgets to export. The game should show a clear on-screen error naming the file or key, not crash or play with zero values. Pinned in Task 3 and Task 8.
2. **The player tries an impossible action** (accepting with no room or no food). The button is disabled with a tooltip giving the reason, and calling `decide` anyway acts as a decline, as in Python. Pinned in Task 4 and Task 8.
3. **Market amounts above what the coins allow.** The buy controls cap at what is affordable, food first, and `DayRunner.buy` caps again. Pinned in Task 5 and Task 8.
4. **"Play again" after a win or loss.** It starts a clean run: new state, new deal, empty ledger, and Bram's lines reset. Pinned in Task 8.
5. **Fixtures out of date after re-tuning.** If `balance.ods` changes but fixtures aren't regenerated, the Python test must fail and say how to regenerate. Pinned in Task 2.
